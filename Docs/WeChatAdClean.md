# 微信广告清理：公众号兼容性试验与小程序素材规则

本模块供 **iPhone 官方微信配合 Quantumult X** 使用。新增的公众号重写依据上游 `getappmsgad` 接口线索独立实现，属于兼容性试验；**尚未在手机验证，不能承诺朋友圈、公众号、视频号、小程序四类广告全部清除。**

小程序部分复用仓库已有的两个精确素材主机规则，没有另建一份重复列表。素材请求被拒绝后，广告卡片、黑屏、倒计时或按钮仍可能保留，激励视频的奖励也不保证发放。

## 处理范围

| 场景 | 本次处理 | 验证边界 |
| --- | --- | --- |
| 公众号文章 | 尝试清理 `mp.weixin.qq.com/mp/getappmsgad` 可识别 JSON 响应的根级广告数量及广告列表 | 来源是上游接口线索，当前官方微信是否仍请求、QX 是否能读取响应、文章是否收拢广告位，均待手机确认；不代表覆盖公众号所有广告 |
| 小程序广告素材 | 复用 `wxsmw.wxs.qq.com`、`wximg.wxs.qq.com` 两个精确主机的拒绝规则 | 这是网络素材阻断，不能保证移除广告容器；规则按主机生效，其他使用同一主机的请求也会被拒绝 |
| 丰巢、美团单车小程序 | 可按需使用已有的专用模块 | 独立安装、独立验收，不计入本次公众号模块效果；丰巢独立开屏仍未解决 |
| 朋友圈、视频号 | 本模块没有相应的可读广告下发响应清理规则 | 未覆盖 MMTLS 内部的广告数据，不拦截整个 MMTLS 通道，也不拒绝微信公共业务域名 |

## 加入原配置

在正在使用的配置的 **`[rewrite_remote]` 区段**加入下面这一行：

```ini
https://raw.githubusercontent.com/belcheckyoung/Belcheck-QX-AdBlock/main/Rewrite/WeChatAdClean.snippet, tag=微信公众号广告清理兼容性试验, update-interval=86400, opt-parser=false, enabled=true
```

需要小程序素材阻断时，在 **`[filter_remote]` 区段**加入下面这一行：

```ini
https://raw.githubusercontent.com/belcheckyoung/Belcheck-QX-AdBlock/main/Filters/WeChatMiniProgramAds.list, tag=微信小程序广告素材, force-policy=reject, update-interval=86400, opt-parser=false, enabled=true
```

**已有同名区段时只添加资源行，不要再次创建区段，更不要替换整份配置。** 两条资源可分别开关；若已经订阅同一地址，只更新现有条目，不要重复添加。仓库现有公开配置已引用小程序素材列表，使用该配置时先检查是否已经启用。

公众号片段自动远程加载脚本，并仅声明 `mp.weixin.qq.com` 为所需 MitM 主机。两个素材主机使用主机过滤，不需要为本功能额外加入 MitM。不要将规则扩大为 `*.wxs.qq.com`、`*.weixin.qq.com` 或 `*.qq.com`。

已安装 NobyDa 原微信脚本或其他改写同一 `getappmsgad` 路径的模块时，先停用其中重复的规则，保留一套响应处理。不要为排查冲突关闭所有原有模块。

## 开启重写与证书信任

已有正在使用且受信任的 QX CA 时，继续使用现有证书。若尚未安装：

1. 在 Quantumult X 的 MitM／证书设置中生成或选择自己的 CA，按应用提供的方式下载证书描述文件到 iPhone。
2. 在 iOS 设置中打开“已下载描述文件”，或进入“通用 → VPN 与设备管理”，安装刚下载的 QX 证书描述文件。
3. 进入“设置 → 通用 → 关于本机 → 证书信任设置”，为这张 QX 根证书开启“完全信任”。安装描述文件和开启完全信任是两个步骤。
4. 返回 QX，开启 Rewrite（重写）和 MitM，手动更新新增的远程资源，检查没有下载错误或 `Invalid Line`，再重连 QX。

检查现有 `[mitm]` 的 hostname 配置。如果 `mp.weixin.qq.com` 被精确排除项或覆盖它的通配排除项排除，远程片段的 hostname 声明可能无法生效。**手动定位冲突项并处理，只调整与本次测试有关的配置；不要清空 hostname、其他排除项或整段 MitM 设置。**

以上步骤完成后，关闭并重新打开微信，再打开需要验证的文章。微信可能复用文章或素材缓存，一次重开不一定会触发新请求。不要为测试卸载微信或删除聊天数据。

## 公众号响应如何修改

仅在目标主机和精确路径、可识别的成功 JSON 广告结构匹配时，将根级 `advertisement_num` 改为 `0`、根级 `advertisement_info` 改为 `[]`。脚本保留 `appid` 与其他未知字段，不递归清理同名的嵌套字段，也不处理其他微信路径。

实现采用局部文本替换：只替换这两个已识别字段的值片段，其余响应正文保留原始文本字节，包括字段顺序、空白、字符串转义和大整数的原始数字表示；不会因整份 JSON 解析后重新序列化而改变其他字段的数字精度。这里的字节保留指 QX 提供给脚本的正文文本，不指传输层压缩数据或 HTTP 报文。

未知结构、错误响应、非 JSON、无法安全定位字段或其他不符合条件的内容原样放行（fail-open）。这减少误改，但也意味着接口变化后可能不再清理广告。脚本不删除 `appid`，也不根据字段名猜测清空未知业务内容。

## 按场景验收

先分别测试公众号重写、小程序素材过滤，再按需开启已有专用模块。记录每一步启用的资源，避免把其他模块效果记到本次试验上。

| 场景 | 查看网络记录 | 查看实际界面与功能 |
| --- | --- | --- |
| 公众号文章 | 是否出现精确 `getappmsgad` 请求，是否命中本模块；可读响应是否仅根级两个广告字段改变 | 文章底部广告及空白占位是否消失；正文图片、视频、链接、留言等原有功能是否正常 |
| 普通小程序广告 | 是否请求两个精确素材主机，是否命中对应拒绝规则；未出现请求不能算命中 | 开屏、Banner、插屏是否仍有卡片、按钮、黑屏或倒计时；登录、图片、订单、支付等原有功能是否正常 |
| 激励视频 | 是否确实命中素材规则，是否出现请求失败或广告重试 | 广告页是否结束、返回是否正常、奖励是否到账；只剩倒计时或未发奖励均不能视为完成 |
| 丰巢、美团单车 | 分别确认已有专用模块的接口命中 | 按各自说明检查广告、占位及正常取件／骑行／结算功能 |
| 朋友圈、视频号 | 本模块没有专用命中判据，不将普通微信连接或 MMTLS 连接当作清理命中 | 分别记录实际广告是否仍在；不能因为其他场景有效就认定这两类已清除 |

**资源下载成功、规则命中、响应改变、界面广告消失是不同的证据。** 没有请求可能是缓存、没有下发该广告或接口改变；素材请求被拒绝也不证明广告容器已经关闭。手机截图与实际操作验收完成前，本模块维持“兼容性试验、手机未验证”的结论。

已有专用模块可按需选用：

- [丰巢小程序广告与推广净化](FengChaoAdClean.md)：订阅 `Rewrite/FengChaoAdClean.snippet`；独立开屏仍有已记录的未解决边界。
- [美团单车微信广告清理片段](../Rewrite/MeituanBikeWeChatAds.snippet)：处理其已识别的广告容器；已经安装时更新现有条目即可。

## 回退与排查

出现文章、图片、登录、支付或页面异常时，先关闭本次新增的对应资源，将该资源行的 `enabled=true` 改为 `enabled=false` 并保存；也可删除该新增资源行，再重连 QX、重开对应页面比较。

若此前已经使用小程序素材列表，恢复到测试前的启用状态，不删除原有条目。停用公众号片段后重连 QX，检查该资源和所带 hostname 声明不再启用；如果为本次试验手动加入过 `mp.weixin.qq.com`，仅在确认其他规则不依赖它时移除这项新增主机。此前手动调整的排除项按记录恢复。

保留原有 CA、证书信任、其他 MitM 主机、排除项及无关规则；不需要重装微信、删除聊天数据或清空整份 QX 配置。
